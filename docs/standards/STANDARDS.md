# 规范边界文件（STANDARDS）

> **性质**：本文件是开发铁律。所有代码、PR、任务卡在提交/验收时对照本文件检查。
> 修改本文件需项目负责人书面确认，并在 git 提交信息中标注 `docs(standards):`。
> 版本：V2.0文件对齐（非软件版本）｜ 2026-09-09。依据：用户本轮书面明确四份V2文件优先，并授权调整整体计划与相关文件。原V1.2规则与来源保留于Git历史。

当前需求入口：[四份V2原件及优先级](../specs/V2.0-文件索引.md)。发生冲突以四文件为准；它们未改变的工程和保密要求继续有效。规范更新不表示代码、运行包或客户验收已同步。模型升级不能豁免事实、权限、测试和业务验收；开发协作见 [MODEL_WORKFLOW](MODEL_WORKFLOW.md)。

## A. 通用规范

| # | 规则 | 检查方式 |
|---|---|---|
| S01 | Git 提交遵循 Conventional Commits：`feat/fix/docs/refactor/test/chore(Mxx): 描述`，必须关联 M 编号（基础设施用 `(base)`） | commit hook / review |
| S02 | 分支模型：主干开发 + 功能分支；合并前必须通过 CI（lint + 类型检查 + 测试） | CI |
| S03 | 标识符与代码用英文；注释、commit message、文档用中文 | review |
| S04 | 敏感信息零入库：凭证/密钥只进 `.env`（已 gitignore），仓库提供 `.env.example`；日志禁止出现完整手机号、密钥、完整真实客户数据 | CI 扫描 + review |
| S05 | 一切以 M01–M12 编号追踪：代码目录、API 路由、测试文件、任务卡与 M 编号对应 | review |

## B. 后端规范（Node ≥22 / NestJS / Prisma）

| # | 规则 | 检查方式 |
|---|---|---|
| S06 | 全仓库统一 ESLint + Prettier（前后端同规则），行宽 100；CI 不通过禁止合并 | CI |
| S07 | TypeScript `strict` 全量开启（前后端一致）；`tsc --noEmit` 门禁；禁止滥用 `any`（确需使用须注释说明理由） | CI |
| S08 | NestJS 分层强制：`controller`（路由/入参校验）→ `service`（业务规则）→ `repository`（Prisma 数据访问）。**controller 禁止直接调用 Prisma client**；模块按 M 编号划分（`modules/m03-leads/`） | review |
| S09 | 所有入参用 Zod schema 校验（全局 ValidationPipe）；统一异常过滤器 + 错误码表（`common/errors`）；**禁止空 catch 吞错**（catch 必须记录或转换后抛出） | CI + review |
| S10 | 数据库 schema 变更必须走 `prisma migrate`（dev 生成迁移、deploy 应用），禁止手改任何环境 schema；`schema.prisma` 变更必须伴随迁移目录提交 | review |
| S11 | 确定性优先：阶段流转、审批、时限、分配等业务规则用显式状态机/规则代码实现，**禁止交给模型自由判断**；模型输出只能产生"建议/草稿"态数据 | review + 测试 |
| S17 | 依赖管理：npm；`package-lock.json` 必须提交；新增依赖需在任务卡/PR 说明用途；运行时依赖最小化 | review |

## C. 前端规范（Vue 3 / TypeScript）

| # | 规则 | 检查方式 |
|---|---|---|
| S12 | TypeScript `strict` 模式；Vite + Pinia + Vue Router；与后端共用 ESLint + Prettier 规则（S06） | CI |
| S13 | API 客户端由后端 OpenAPI 自动生成（@nestjs/swagger 导出 → openapi-typescript 生成），**禁止手写接口类型**；生成脚本纳入 CI | CI |
| S14 | 分层：`views`(页面) / `components`(组件) / `composables`(逻辑) / `stores`(状态)；单文件组件 ≤300 行，超出必须拆分 | review |

## D. 测试规范

| # | 规则 | 检查方式 |
|---|---|---|
| S15 | **Vitest 前后端统一**（后端 @nestjs/testing 装配；前端 @vue/test-utils）+ Playwright 关键链路 E2E；**新功能必须带测试**；测试文件命名含 M 编号（如 `m03-lead-import.spec.ts`） | CI |
| S16 | Agent 评测数据与构建用例分离；合成数据用于回放测试；测试环境禁止使用真实客户数据 | review |

## E. AI 边界（不可妥协项）

| # | 规则 |
|---|---|
| A01 | OpenClaw沿用现有网关，工具按用途白名单、调用者权限、资源范围和审计验证；模型不得绕过后端自行写业务、发送或访问未授权资料。技能文件读取与业务查询分别限定资源，不能因工具名允许就放开目录。旧 `biz-query`/`knowledge-search` 名称不代表当前全部接线；实际工具清单须随版本验证 |
| A02 | 当前AI对外内容先落草稿，由获授权的人确认执行；程序控制价格、状态、排期与审批。报价、优惠与非标承诺由获授权人员审核；具体业务阈值由部署方自行配置。未来AI低风险对客试点须另经授权渠道、评测及接管/停止验证，当前不因此开放自动发送 |
| A03 | AI 输出落库必须带全量审计：task_id、task_type、模型、输入摘要（脱敏后）、输出、token 消耗、人工采用/修改/拒绝标记 |
| A04 | 脱敏强制：手机号/微信/车牌/住宅地址不出 ai-dispatch 适配层；客户以假名 ID 参与 AI 任务 |
| A05 | 关键事实（价格/质保/品牌规则/优惠权限）必须来自知识库且带来源引用；无来源、过期或冲突时系统拒绝确定性回答 |
| A06 | AI不得冒充真实客户或老板身份进行实际沟通，不用操纵式表达；电话不是默认首触。明确标示的模拟训练允许AI扮客户，模拟和教练点评分开，不能将模拟台词/结果当真实业务证据 |
| A07 | 停止开关：全局 AI 开关 + 每 skill 独立开关必须存在并实测有效 |
| A08 | skill/提示词/模型配置变更先过固定案例回归，覆盖格式、来源、事实与承诺边界、正常场景误拦、实际业务可用性；报告随PR。测试版本与知识/技能版本明确；HTTP成功或字段非空不代替业务验收 |
| A09 | **AI能力发布须相应负责人批准**：候选→固定评测→审批→影子或小范围试运行→发布→监控回滚；热加载仅加载已发布版本。关键经营知识由老板或老板娘批准，技术变更由技术负责人核验，涉及业务范围/风险由项目负责人确认。低风险调整也须白名单、版本、评测及回滚，不做未验证在线自学习 |
| A10 | 生成、编辑、复制、人工登记发送、证据支持的实际发送及客户回复分别留痕。无发送证据不把草稿标为实发；登记发送不冒充已读取真实微信。每轮有效跟进轻量记录，不强制逐句举证；缺记录不等于员工未工作或客户未回复 |
| A11 | 个人聊天、训练记录、候选经验和已批准共享方法分开授权；方法必须核验评测后批准，版本与来源可追溯并可撤回。老板经营权限不自动开放其他人的私人会话；跨客户仅复用获准抽象方法或真正匿名聚合 |

## F. 安全红线（来自任务书 §6）

| # | 规则 |
|---|---|
| SEC01 | 最小必要采集：姓名、电话、微信、车牌、车型、时间、金额、住宅地址、影像按业务必需采集 |
| SEC02 | 账号按人分配、最小权限、不得共用；敏感导出/批量外发/删除/权限变更必须审批+审计 |
| SEC03 | 开发/测试/生产隔离；Git、文档、普通日志禁止保存凭证或完整真实客户数据 |
| SEC04 | 不以客户财富、性别等敏感特征做差别定价、自动标签或员工奖惩 |
| SEC05 | 删除请求、停止联系请求必须可执行并留痕 |
| SEC06 | 按来源评估总部/客户授权导出、官方接口、允许的公开检索、用户素材及受控公开采集；不绕验证码、反爬、账号保护，不取同行非公开客资。可接接口不等于已获授权，不以候选公开需求能力授权批量骚扰 |

## G. 完成定义（Definition of Done）

一个任务卡"完成"必须同时满足：

1. 代码通过 CI（ESLint / Prettier / tsc --noEmit / Vitest）
2. 对应测试（单测/集成/E2E 按任务卡要求）全部通过
3. 涉及 AI 的任务附评测结果；涉及权限的任务附越权测试结论
4. 数据库变更附 Prisma 迁移；配置变更同步 `.env.example`
5. 相关文档（数据字典/权限矩阵/任务卡状态）已更新
6. 提交信息符合 S01
