# 项目案例

[项目介绍](../../README.md) · [架构说明](ARCHITECTURE.md) · [演示流程](DEMO.md)

以下案例使用合成场景说明工程设计，不引用真实客户对话、价格或经营结果。作者确认项目为个人独立开发；每个案例分别列出可核查的代码与测试。

## 案例一：让跟进草稿可修改、可追溯

**业务问题。** 员工需要参考建议继续沟通，但模型建议、人工改写和后续跟进如果混在一个文本框里，就很难还原做了什么。

**设计选择。** 将“生成草稿”“人工编辑”“复制”“登记发送”分成独立动作。原建议保留，人工改写有版本，登记发送要求填写依据，服务本身不发送外部消息。

**实现。** 客资归属校验通过后构建上下文，调度 `sales.draft_message`。`AiTask.output` 保存原建议；`LeadEvent` 保存人工改写、复制和登记事件，详情页组织历史。

**个人贡献。** 独立完成该业务流程的页面、接口、数据记录与 Agent 任务衔接。

**可验证的结果。** 测试明确断言：人工编辑不覆盖 AI 输出；复制不创建登记发送事件；非负责人不能修改别人的草稿。这里是程序契约，没有把它扩写为“沟通效率提升”或“成交率提高”。

**取舍。** 登记依据依赖操作者填写，不等于平台独立验证真实发送；该系统没有读取真实聊天记录来证明客户已收到消息。

证据：[SalesDraftService](../../backend/src/modules/lead/ai/sales-draft.service.ts)、[sales-draft.spec.ts](../../backend/test/sales-draft.spec.ts)、[LeadEvent 与 AiTask](../../backend/prisma/schema.prisma)。

## 案例二：让 Agent 任务失败后仍可排查

**业务问题。** 模型可能超时、返回非预期 JSON，或需要额外查阅业务信息。只在界面显示“失败，请重试”，难以定位原因，也难以控制工具和费用。

**设计选择。** 使用统一调度层记录任务、时限和状态；在模型外围加入输入脱敏、结果校验、用量记录和恢复入口。通过有限 MCP 工具提供业务查询。

**实现。** 后端登记任务后发起网关 run，按任务 ID 隔离网关会话。返回结果经过归一化与 Schema 校验；工具调用保存审计，超限查询被拒绝。部分入口自动重试，控制台允许手动重试或登记人工接管。

**个人贡献。** 独立完成调度层、网关适配、只读查询工具和任务控制台的集成。

**可验证的结果。** 对应测试覆盖成功状态链、超时降级、结果不符合契约、重复回调，以及在途调用计数。没有原始对照实验支持“稳定性提升百分比”，因此不写该类数字。

**取舍。** 当前 MCP 通过共享令牌访问并归属最近的在途任务；并发时可能归错。超时或人工接管登记也不等于网关执行已被取消。费用依赖可取得的用量和配置单价。

证据：[调度服务](../../backend/src/modules/ai-dispatch/ai-dispatch.service.ts)、[结果受理](../../backend/src/modules/ai-dispatch/ai-callback.service.ts)、[网关测试](../../backend/test/ws-openclaw-gateway.spec.ts)、[调用计数测试](../../backend/test/mcp-governor.spec.ts)。

## 案例三：让经验先经过审核，再参与回答

**业务问题。** 对话中的经验可能值得复用，但直接把训练原文和未经验证的建议作为知识，会让后续回答沿用错误或不适用的信息。

**设计选择。** 把模拟练习、教练点评、经验提炼和知识生效分开。提炼结果先是草稿，人工批准后才具备生效状态；独立知识问答无可用授权条目时返回不确定。

**实现。** `RoleplaySession` 与 `RoleplayTurn` 保存训练过程，对话与点评使用不同任务类型；提炼任务可以返回拒绝原因，成功时经 `KnowledgeService` 创建知识草稿。问答入口通过检索结果组织回答并保留来源与版本。

**个人贡献。** 独立完成训练会话、经验卡、知识工作流与模型任务之间的衔接。

**可验证的结果。** 经验提炼测试覆盖草稿状态、无效输出拒收和他人会话不可读取。数据模型与服务体现了审核前后的分离；没有证据证明训练提高了员工业务能力。

**取舍。** 独立问答、角色对话和 MCP 查询的授权过滤尚未统一。当前版本需要谨慎管理生效知识，不能把现有实现描述为所有入口均有完整授权检查。

证据：[RoleplayService](../../backend/src/modules/agent/roleplay.service.ts)、[经验提炼测试](../../backend/test/experience-extract.e2e.spec.ts)、[KnowledgeSearchService](../../backend/src/modules/knowledge/knowledge-search.service.ts)。

## 面试中如何展开

可以从任意一个案例沿“业务问题 → 数据记录 → 服务契约 → 失败路径 → 测试断言 → 当前限制”讲解。项目周期、真实使用范围、上线后的效果与具体决策背景仍待作者补充，不用推测的数字填补空白。
