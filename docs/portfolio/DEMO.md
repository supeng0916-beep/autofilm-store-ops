## 连接服务后的演示脚本

下面是建议执行顺序，本轮文档整理没有将它描述为已完成的现场演示。按启动指南使用独立数据库；只录入自己编写的虚构资料，网关及模型需另行配置。

**准备一条合成线索。** 名称使用“演示客户 A”，需求为“咨询演示服务流程，尚未确认到店时间”。不填写真实联系方式，不导入业务聊天记录。

**展示跟进草稿。** 输入目标“生成需要先确认的问题，不承诺价格或日期”，查看草稿，进行一次人工修改，再查看原建议与修改版本。复制后解释：这里只记录复制，没有自动发送外部消息。

**展示任务轨迹。** 使用有权限的演示账号查看对应任务，说明输入摘要、状态、错误、模型与用量字段。若网关不可用，如实展示降级状态，不用截图伪装成功。

**展示知识边界。** 先在空知识库提问，说明缺少来源时的处理；再创建一条完全虚构的知识草稿：“演示预约需人工确认可用时间”。将这条自编知识标记为已授权，按实际权限批准生效，并等待向量入库后再次检索，查看来源。独立向量问答需要 Embedding；仅批准生效不会自动改变授权字段。

**展示陪练。** 使用虚构场景练习首次沟通，结束后查看点评，再尝试提炼经验卡。解释提炼结果先进入草稿，不能自动成为可信方法。

## 演示前检查

- 确认数据库与浏览器会话属于演示环境，关闭默认不需要的定时通知。
- 检查屏幕上的用户、标签、来源、任务明细和地址栏，不展示真实凭据或原项目路径。
- 不把截图中的金额、采用率、耗时或任务成功数讲成真实成果。
- 介绍角色路由时不演示不存在的 Agent 自动相互委派；介绍检索时区分各入口。
- 如果需要新的录像或截图，先核对合成输入、网络请求和最终画面，再加入发布候选。
